# DESIGN — Docs migration: Starlight + llms.txt + consumer skill

- **Date:** 2026-06-12
- **Scope:** `docs-starlight-migration`
- **Slice:** `001-starlight-llms-skill`
- **Tier:** L (multi-day, cross-cutting — new build toolchain + content migration + npm-shipped skill)
- **Slicing decision:** ONE big slice / one PR (user choice).

## Goal

Replace the pure-TypeDoc HTML docs with an **Astro + Starlight** documentation site that:

1. Embeds the TypeDoc API reference as themed, searchable Markdown pages (no standalone HTML).
2. Provides hand-authored, per-runtime usage guides (Node, Bun, Cloudflare, Browser+React) covering setup, recommended API, and full examples.
3. Generates `llms.txt` (+ full/small variants) via the `starlight-llms-txt` plugin, **split into per-runtime document sets** so an LLM reader loads only the tokens it needs.
4. Has a landing page whose **hero exposes the `llms.txt` URL with a copy-to-clipboard button** as the first thing a visitor sees.
5. Ships a **generator/installer Claude skill** in the npm package that scaffolds telemetry-js-specific `.claude/rules` + a usage skill into a consumer project, tuned to that project's runtime and pointing at the published `llms.txt`.
6. Deploys to **GitHub Pages**.

## Non-goals

- No versioned docs (single "latest" only).
- No i18n.
- No interactive playground / live code runner.
- No blog.
- No migration of `plans/**` content into the site.

### API generation — explicit TypeDoc prebuild (D8)

**Decision (D8): TypeDoc runs as an explicit prebuild step, NOT as the `starlight-typedoc` build plugin.** This decouples API generation from Astro plugin ordering so the `api/**` Markdown pages always exist on disk *before* `astro build` runs — guaranteeing `starlight-llms-txt` sees them.

**Decision (D9): API reference is broken down per runtime.** Instead of one flat `api/` dump, TypeDoc runs once per runtime bucket, each writing to its own subfolder. The folder structure drives both the sidebar (nested groups via `autogenerate`) and the per-runtime llms.txt sets.

Buckets → output dir → entry points:

| Bucket | `out` | Entry points |
|---|---|---|
| Node | `api/node` | `node/index.ts` |
| Bun | `api/bun` | `bun/index.ts` |
| Cloudflare | `api/cloudflare` | `cloudflare/index.ts` |
| Browser | `api/browser` | `browser/index.ts`, `browser/fetch/index.ts`, `browser/react/index.ts`, `browser/sdk/index.ts` |
| Shared | `api/shared` | `error/index.ts`, `db/index.ts`, `context/index.ts`, `vite/index.ts` |

- Generate via `typedoc` CLI + `typedoc-plugin-markdown` (+ `typedoc-plugin-frontmatter` to emit Starlight-compatible frontmatter `title`).
- Each bucket is a separate `typedoc` invocation sharing common options (`docs/typedoc.base.json`) but overriding `entryPoints` + `out`.
- Output root `docs/src/content/docs/api/` (gitignored — regenerated each build).
- Wired as the docs package `prebuild` script so `pnpm --filter docs build` always regenerates first.
- `starlight-typedoc` plugin + `typeDocSidebarGroup` are NOT used. API sidebar group is a plain `autogenerate: { directory: 'api' }` — the per-runtime subfolders become nested sidebar groups automatically.

```jsonc
// docs/package.json (scripts excerpt)
{
  "scripts": {
    "docs:api": "node ./scripts/gen-api.mjs",
    "prebuild": "pnpm run docs:api",
    "build": "astro build",
    "dev": "pnpm run docs:api && astro dev",
    "preview": "astro preview"
  }
}
```

`docs/scripts/gen-api.mjs`: iterates the bucket table, shelling `typedoc --options ./typedoc.base.json --out src/content/docs/api/<bucket> <entryPoints...>` per bucket. (A small script keeps the per-bucket entry-point lists in one readable place; alternative is N inline CLI calls — implementer's call.)

```jsonc
// docs/typedoc.base.json (shared opts; no entryPoints/out — supplied per bucket)
{
  "$schema": "https://typedoc.org/schema.json",
  "plugin": ["typedoc-plugin-markdown", "typedoc-plugin-frontmatter"],
  "entryPointStrategy": "resolve",
  "tsconfig": "../tsconfig.json",
  "excludePrivate": true,
  "excludeInternal": true,
  "readme": "none",
  "githubPages": false
}
```

> Verify during impl: exact `typedoc-plugin-markdown` output flags so generated frontmatter satisfies Starlight's content schema (needs a `title`). `typedoc-plugin-frontmatter` supplies it; confirm field mapping against installed version.

### Astro config

```js
// docs/astro.config.mjs
import { defineConfig } from 'astro/config'
import starlight from '@astrojs/starlight'
import starlightLlmsTxt from 'starlight-llms-txt'

export default defineConfig({
  site: 'https://tigorlazuardi.github.io',
  base: '/telemetry-js',
  integrations: [
    starlight({
      title: '@tigorhutasuhut/telemetry-js',
      social: [{ icon: 'github', label: 'GitHub', href: 'https://github.com/tigorlazuardi/telemetry-js' }],
      plugins: [
        starlightLlmsTxt({
          minify: { whitespace: false }, // explicit: avoid whitespace-collapse mangling (known issue)
          customSets: [
            { label: 'Node usage',       description: 'telemetry-js on Node.js',            paths: ['runtimes/node', 'api/node/**', 'api/shared/**', 'guides/**', 'getting-started/**'] },
            { label: 'Bun usage',        description: 'telemetry-js on Bun',                 paths: ['runtimes/bun', 'api/bun/**', 'api/shared/**', 'guides/**', 'getting-started/**'] },
            { label: 'Cloudflare usage', description: 'telemetry-js on Cloudflare Workers',  paths: ['runtimes/cloudflare', 'api/cloudflare/**', 'api/shared/**', 'guides/**', 'getting-started/**'] },
            { label: 'Browser usage',    description: 'telemetry-js in the browser + React', paths: ['runtimes/browser', 'api/browser/**', 'api/shared/**', 'guides/**', 'getting-started/**'] },
            { label: 'API reference',    description: 'Full generated API reference',        paths: ['api/**'] },
          ],
        }),
      ],
      sidebar: [
        { label: 'Getting Started', autogenerate: { directory: 'getting-started' } },
        { label: 'Runtimes', autogenerate: { directory: 'runtimes' } },
        { label: 'Guides', autogenerate: { directory: 'guides' } },
        { label: 'API Reference', autogenerate: { directory: 'api' }, collapsed: true },
      ],
    }),
  ],
})
```

Because `api/**` is generated into `content/docs/` by the prebuild step, both Starlight and `starlight-llms-txt` treat the API pages as ordinary content — no plugin-ordering dependency.

### llms.txt — whitespace handling (flagged risk)

- `starlight-llms-txt` default `minify.whitespace: true` collapses runs of whitespace to a single space **outside** fenced code blocks. This mangles formatting in the small/set outputs.
- **Fix:** set `minify: { whitespace: false }` explicitly (above).
- `minify.collapseCodeBlocks` default is `false` — leave it, so code fences are never collapsed regardless.
- Acceptance: generated `llms-*.txt` and per-set files preserve paragraph/list/code formatting (spot-check a runtime set).

### Consumer Claude skill (generator/installer)

Shipped inside the npm package so consumers using Claude Code get LLM leverage.

- Location in repo: `skills/telemetry-js/SKILL.md` (+ supporting templates under `skills/telemetry-js/`).
- Added to `package.json` `files` array so it ships on npm.
- **Behavior when invoked in a consumer project:**
  1. Detect runtime(s) from the consumer's `package.json` deps / project signals (node, bun, cloudflare/workers, browser/react).
  2. Generate path-scoped `.claude/rules/telemetry-js-*.md` capturing recommended-API + ordering constraints (e.g. init/instrumentation ordering, fetch instrumentation before SDK load on browser, endpoint resolution rules).
  3. Generate a project-local usage skill (`.claude/skills/telemetry-js-usage/SKILL.md`) summarizing the recommended API for the detected runtime and **linking the matching published `llms.txt` document set**.
  4. Be idempotent — re-running updates rather than duplicates.
- The skill's own knowledge references the published docs/llms.txt as the canonical source, so it stays thin and points at always-current docs.

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| Plugin order: llms.txt assembled before typedoc pages exist | RESOLVED (D8): typedoc runs as explicit prebuild → api pages on disk before astro build; no ordering dependency. |
| typedoc-plugin-markdown frontmatter incompatible with Starlight content schema | Add `typedoc-plugin-frontmatter` to emit `title`; verify field mapping in impl. |
| `base: '/telemetry-js'` breaks internal links / asset paths | Use Starlight-relative links + Astro `base`-aware helpers; verify built site under subpath locally (`astro preview`). |
| llms.txt whitespace mangling | `minify.whitespace: false` set explicitly + spot-check. |
| README/site content drift | README trimmed to pointer; site is single source of truth (D3). |
| `docs/` previously gitignored + was typedoc target | Remove `docs/` from `.gitignore`; add `docs/dist` + `docs/src/content/docs/api` to ignore instead; delete old root `typedoc.json` HTML pipeline. |
| pnpm workspace: docs deps bloat root install | docs is its own workspace package; its heavy deps (astro etc.) are dev-only to the docs package, not the published lib. |
| Generator skill writes into consumer repo | Idempotent + only writes under `.claude/`; document clearly; never touch consumer source. |

## Acceptance criteria

1. `pnpm --filter docs build` succeeds; `astro preview` serves the site under `/telemetry-js/` with working navigation.
2. `pnpm --filter docs docs:api` regenerates `api/{node,bun,cloudflare,browser,shared}/**` Markdown for all 11 entry points; API Reference sidebar renders them as per-runtime nested groups.
3. Per-runtime pages (node/bun/cloudflare/browser) each have setup + recommended API + complete example.
4. `llms.txt`, `llms-full.txt`, and the 5 document sets are emitted; formatting preserved (whitespace not collapsed).
5. Landing page shows llms.txt URL + working copy button as the first hero element.
6. README trimmed; long sections live only in the site.
7. `skills/telemetry-js/SKILL.md` present, shipped via `package.json` `files`, and (dry-run) generates runtime-appropriate `.claude/rules` + usage skill in a sample consumer.
8. CI builds docs; Pages deploy workflow present and green.
9. Old standalone TypeDoc HTML pipeline removed (`docs:generate` repointed or dropped; root `typedoc.json` reconciled).
